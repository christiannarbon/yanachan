Yana-chan 4K {{ .Chart.AppVersion }} is installed as {{ include "yana.fullname" . }} in {{ .Release.Namespace }} ({{ .Values.auth.mode }} mode).
{{- if include "yana.serverMode" . }}

Users sign in with GitHub at {{ .Values.auth.publicURL }}
The OAuth App's callback URL must be exactly:

  {{ .Values.auth.publicURL | trimSuffix "/" }}/api/auth/callback

{{ if include "yana.valkey.enabled" . -}}
Sessions and settings are stored in the bundled Valkey ({{ include "yana.valkey.fullname" . }},
one instance{{ if .Values.valkey.persistence.enabled }}, data on a PVC{{ if eq .Values.valkey.persistence.whenDeleted "Retain" }} that is kept on uninstall{{ end }}{{ else }}, NO persistence: a Valkey restart signs everyone out{{ end }}).
Its password is the {{ .Values.auth.secretKeys.redisPassword }} key of the Secret below.
The app pod waits for it to answer before it starts, and turns NotReady
(/api/ready) whenever it loses it later.
{{- else }}
Sessions are stored in the Redis/Valkey at {{ .Values.auth.redis.url }}.
The app exits at start if it cannot reach it (check the URL and the password),
and turns NotReady (/api/ready) whenever it loses it later.
{{- end }}

The pod reads keys from the Secret {{ include "yana.secretName" . }}. If it is not
there yet, the pod waits in CreateContainerConfigError until it is:

  kubectl -n {{ .Release.Namespace }} create secret generic {{ include "yana.secretName" . }} \
    --from-literal={{ .Values.auth.secretKeys.clientSecret }}=<client-secret> \
    --from-literal={{ .Values.auth.secretKeys.sessionKeys }}="$(head -c32 /dev/urandom | base64)" \
    --from-literal={{ .Values.auth.secretKeys.redisPassword }}={{ if include "yana.valkey.enabled" . }}"$(head -c24 /dev/urandom | base64)"{{ else }}<redis-password>{{ end }}

Who may sign in:{{ with .Values.auth.allowedOrgs }} members of {{ join ", " . }}.{{ end }}{{ with .Values.auth.allowedUsers }} users {{ join ", " . }}.{{ end }}{{ if .Values.auth.allowAnyUser }} ANY GitHub user (auth.allowAnyUser=true).{{ end }}

{{ if or .Values.ingress.enabled .Values.httpRoute.enabled -}}
The route host, auth.publicURL and the OAuth App's callback must all name the
same host, or nobody can sign in. The app answers to: {{ include "yana.allowedHosts" . }}
{{- if not (hasPrefix "https://" .Values.auth.publicURL) }}
auth.publicURL is not https: the session cookie is sent without Secure.
{{- end }}
{{- else -}}
Until an Ingress or HTTPRoute exists, try it through a port-forward; this only
works when auth.publicURL is http://localhost:19080:

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "yana.fullname" . }} 19080:{{ .Values.service.port }}
{{- end }}
{{- else }}

Local mode has no login of its own: anything that can reach it is signed in as
whoever stored the GitHub token.
{{- if and .Values.exposure.authenticatedBy (or .Values.ingress.enabled .Values.httpRoute.enabled (ne .Values.service.type "ClusterIP")) }}
It is exposed on the claim that {{ .Values.exposure.authenticatedBy }} authenticates every
request in front of it. Its hosts: {{ include "yana.allowedHosts" . }}
{{- end }}
Reach it yourself through a port-forward:

  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "yana.fullname" . }} 19080:{{ .Values.service.port }}
  open http://localhost:19080

Sign in with the OAuth device flow (needs auth.clientId or the {{ .Values.auth.secretKeys.clientId }} key in the
{{ include "yana.secretName" . }} Secret), or put a token under {{ .Values.auth.secretKeys.token }}:

  kubectl -n {{ .Release.Namespace }} create secret generic {{ include "yana.secretName" . }} \
    --from-literal={{ .Values.auth.secretKeys.token }}=<token> --from-literal={{ .Values.auth.secretKeys.clientId }}=<client-id>
  kubectl -n {{ .Release.Namespace }} rollout restart deploy/{{ include "yana.fullname" . }}

The state volume {{ include "yana.claimName" . }} is kept on helm uninstall. Delete it yourself
to forget the stored session and settings.
{{- end }}
{{- if and .Values.networkPolicy.enabled (ne .Values.service.type "ClusterIP") }}

The NetworkPolicy admits only pods in {{ .Release.Namespace }} and networkPolicy.ingressFrom.
Traffic reaching the {{ .Values.service.type }} Service from outside the cluster is dropped
until ingressFrom admits its source, for example with an ipBlock.
{{- end }}
